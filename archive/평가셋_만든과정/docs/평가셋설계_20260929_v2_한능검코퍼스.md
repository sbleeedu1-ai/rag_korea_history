# 새 평가셋 v2 설계 (2026-09-29, 한능검 기준 코퍼스용)

규칙서 v1.1로 자른 새 코퍼스(파일럿 7건 + 확장 125건 = 132건, 793청크)에 맞춘 평가셋입니다. 기존 평가셋(`single`·`holdout`·`scenarios`)은 파일럿 23청크(c01-c23)용이라 그대로 둡니다.

- 파일: `data/eval/v2_20260929_한능검코퍼스.jsonl` (41문항)
- 만드는 스크립트: `scripts/build_eval_v2.py` (문항은 스크립트 안 `ITEMS`에 있음, 결과 파일이 있으면 덮어쓰지 않고 멈춤)
- 불러오기: `evaluate.load_questions("v2_20260929_한능검코퍼스")`

## 구성

| 분류 | 문항 | 맞은 답의 조건 |
|---|---|---|
| 사실 / 사실(수치) | F01-F28 (28개) | 기대 답 내용 + `must_terms`가 답에 있음 |
| 잘못된 전제 | T01-T05 (5개) | 틀린 전제를 바로잡고 맞는 사실로 답함. `wrong_example`처럼 전제를 받아들이면 오답 |
| 자료 없음 | N01·N02·N05 (3개) | `abstain: true`. 자료에 없다고 말해야 정답, 지어내면 오답 |
| 자료 없음(근접) | N03·N04 (2개) | 위와 같음. 다만 `near_chunks`에 헷갈리기 쉬운 청크가 있음(예: 정약용 탄핵 기사는 있으나 여전론은 없음) |
| 일부만 있음 | P01-P03 (3개) | `partial.have`는 답하고 `partial.lack`은 자료에 없다고 말해야 정답. 한쪽만 하면 부분 |

주제는 한능검 출제빈도 표(`docs/한능검_출제빈도_주제별_20260929.csv`)의 주제묶음 20개 가운데 17개에 걸쳐 뽑았습니다(`topic` 칸). 빠진 것: 조선 후기 경제(대동법·통공은 다른 묶음으로 넣음), 실학(자료 없음 문항의 소재), 성종 통치 정비.

## 칸

기존 평가셋 칸(`id`·`category`·`mode`·`question`·`expected`·`wrong_example`·`evidence`·`must_terms`·`gold_chunks`)을 그대로 쓰고, 다음을 더했습니다.

| 칸 | 뜻 |
|---|---|
| `topic` | 한능검 주제묶음 |
| `evidence` | 근거 = 기사 ID + 문단(1부터 셈, 기존 평가셋과 같음). 스크립트가 청크에서 자동 계산 |
| `gold_chunks` | 규칙서 청크 ID(`기사ID-순번`). 검색 적중(retrieval_hit) 계산용 |
| `abstain`, `partial`, `near_chunks` | 위 표 참고 |
| `hanneung` | 근거 기사가 한능검 판정표에 걸린 회차·문항 번호(번호만, 문항 문장은 넣지 않음) |

## 만들 때 지킨 것

- 질문·기대 답은 우리가 원문을 읽고 쓴 말입니다. 한능검 기출 문장과 국역·신역 문장은 넣지 않았습니다(CLAUDE.md).
- `must_terms`는 정답 청크의 우리 번역(`data/expansion/corpus_20260929_v1_규칙서.jsonl`)에 실제로 나오는지 스크립트가 검사합니다. 없으면 파일을 만들지 않습니다.
- 자료 없음 문항은 판정표에서 "없음"으로 나온 주제(실학자 저술, 그림, 실록 범위 밖)에서 골랐습니다. 일부만 있음은 판정표의 "일부"와 같은 성격(이황·정조 소설·김홍도)입니다.
- 함정은 기존 평가셋에서 약했던 유형(발언자 혼동, 주체 뒤바뀜, "처음 만들었다" 같은 전제)을 새 기사로 다시 만든 것입니다.

## 주의할 점

1. **청크 ID 호환**: `gold_chunks`는 규칙서 시험 파일(`청크초안_20260929_v1b_132건_규칙서시험.jsonl`)의 ID입니다. 132건 번역 코퍼스(793청크)도 같은 규칙서 코드로 잘랐으므로 ID가 같아야 합니다. 그쪽 코퍼스가 나오면 ID를 한 번 대조해야 합니다(`evidence`는 기사+문단이라 청크가 바뀌어도 유효).
2. **must_terms는 제 번역 기준**: 다른 번역(파일럿 새 번역, 확장분 번역 등)은 낱말이 다를 수 있습니다(예: "좋지 않습니다" / "불가합니다"). 그 코퍼스가 나오면 `must_terms` 검사를 그 번역으로 다시 돌려야 합니다. 스크립트의 `CORPUS` 경로만 바꾸면 됩니다.
3. **자동 채점 한계**: `abstain`·`partial`·잘못된 전제는 키워드만으로 판정할 수 없어 사람 채점(또는 LLM 채점, 로드맵 4단계 "LLM 자동 채점 vs 사람")이 필요합니다. `evaluate.py`는 아직 이 칸을 쓰지 않습니다.
4. **역할 대화(시점) 문항은 아직 없음**: 새 코퍼스의 `known_from` 칸이 채워진 뒤, 시점 누설 문항을 따로 만드는 것이 맞습니다.
