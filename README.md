# 역사 취재록: 조선왕조실록 RAG

조선왕조실록 **한문 원문을 직접 번역**해 검색 자료로 만들고, 그 위에 **역사 속 인물을 취재하는 학습 서비스**를 만든 프로젝트입니다. 2026년 9-10월에 만든 개인 프로젝트입니다.

ChatGPT 같은 범용 AI는 역사 인물 역할을 맡기면 그 인물이 알 수 없는 미래를 말하거나, 질문 속 틀린 전제를 그대로 받아들이고, 근거를 보여 주지 못합니다. 이 프로젝트는 세 가지를 겨냥했습니다.

- **근거**: 답이 기댄 실록 기사를 원문과 함께 보여 준다.
- **시점**: 인물은 그 장면까지 알려진 기록만 쓴다(미래 사실 누설 0).
- **전제 교정**: "숙종 때 금위영에 대장을 따로 두기로 했다던데"처럼 틀린 말이 섞인 질문은 기록으로 바로잡는다(실제로는 병조판서가 겸함).

## 무엇을 만들었나

| 모드 | 하는 일 |
|---|---|
| **취재하기** | 사건 속 인물에게 묻는다. 예: 1444년 언문 반대 상소를 올린 최만리(부름 전)와 이를 논박한 세종(논박 뒤)을 오가며 취재하고, 해설자에게 뒷일을 듣고, 근거로 확인한 내용을 취재 수첩에 모은다. 두 번째 사건은 계유정난(수양대군·권람) |
| **실록에 묻기** | 사실 질문 하나에 답과 근거 기사 |
| **기출처럼 풀기** | 한국사능력검정시험처럼 사료를 읽고 5지선다 문제를 풀고 근거 기사로 해설을 본다 |

## 결과 (2026-10-08 최종 측정)

같은 구성(정답형 10 · 이름을 뺀 질문 3 · 숫자 2 · 자료 없음 2 · 함정 3) 20문항으로 비교했습니다. 정답만 셉니다(부분 정답은 세지 않음).

| | ChatGPT 유료 (웹 검색 끔) | ChatGPT 무료 (웹 검색 끔) | 고치기 전 | 고친 후 |
|---|---|---|---|---|
| 개발 단발 20 | 13/20 | 10/20 | 12/20 | **20/20** (3회 모두) |
| 개발 역할 대화 10 | 7/10 | 5/10 | 6/10 | **10/10** (3회 10·10·9) |
| **홀드아웃 20** (개선에 쓰지 않은 문항, 한 번만 실행) | 8/20 | 6/20 | - | **사람 채점 17/20** · AI 18/20 |

- 화자를 바꿔 묻기·미래 묻기 함정 6턴: ChatGPT 3/6 → 우리 6/6. 역할 대화 150턴에서 미래 사실 누설 0.
- ChatGPT는 유료 GPT-6 Sol(생각 수준 High), 무료 GPT-5.6 Luna(Think), 질문마다 새 임시 채팅. **웹 검색을 켜면 ChatGPT도 홀드아웃 18·17/20**이라, 정확도로 웹 검색 AI를 이긴다고 주장하지 않습니다. 이 프로젝트의 차이는 근거를 보여 주는 것, 시점을 지키는 것, 작은 모델로 싸게 하는 것입니다.
- 아직 틀리는 것: 한능검식으로 이름을 가리고 단서만 주는 질문(홀드아웃 1/3). 자세히는 [한계와 다음 과제](docs/한계와_다음과제.md).
- 결과 파일: `results/20261008_홀드아웃v2/`, `results/20261008_GPT빈손/`, 개발셋 3회는 `results/20261007_전제판정나눔*/`.

## 어떻게 동작하나

```
질문 → [시점 필터: 장면 뒤에 알려진 기록은 뺌]
     → 임베딩 검색 + BM25(두 글자씩) + 쉬운 말 풀이 BM25 → 순위 합치기(후보 약 27개)
     → 리랭커(답변 모델)가 6개를 고르며 질문 속 전제도 판정
     → 답변(사실 질문 규칙 / 인물 역할 규칙 / 해설자) → 근거 대조
```

- 자료: 한국사능력검정시험 출제빈도로 고른 실록 기사 **132건**을 화자·인용 단위로 잘라 **803청크**로 만들고, 한문 원문에서 직접 번역했습니다. 어려운 용어 4,512개에 쉬운 말 풀이를 붙였습니다.
- 모델: 답변·리랭커 `gpt-6-luna`, 임베딩 `text-embedding-3-large`, 벡터 DB Chroma(로컬).
- 자세히: [코드 구조](docs/구조.md), [데이터](docs/데이터.md), [결정과 과정](docs/결정.md).

## 실행

Python 3.12에서 확인했습니다.

```bash
pip install -r requirements.txt
python -m streamlit run app.py        # 화면 열기
```

**API 키가 없어도** 화면이 미리보기로 열립니다(BM25 검색만, 답 생성 없음). 실제 답을 받으려면:

```bash
cp .env.example .env                   # .env를 열어 OPENAI_API_KEY 입력 (git에 올라가지 않음)
python -m sillok_rag.cli build-db      # 803청크를 임베딩해 로컬 검색 DB를 만듦 (한 번, 약 $0.04)
python -m streamlit run app.py         # 화면 '설정'에서 실제 답변을 켬 (질문마다 유료, 1센트 미만)
```

- `SILLOK_FAST=1`로 켜면 측정 뒤 시험한 빠른 설정(리랭커 생각 끔 등)을 씁니다. 답변 대기가 18-20초에서 8-12초로 줄지만 측정 설정과 다릅니다.
- 명령줄로 묻기: `python -m sillok_rag.cli ask -c D2 "김문은 어떤 처벌을 받았나?"` (`--dry-run`이면 키 없이 프롬프트만 확인)

### 실험 다시 돌리기

```bash
python -m sillok_rag.cli run-single -c D2 --run 이름                  # 개발셋 v3 단발 67문항 → results/<오늘>_이름/
python -m sillok_rag.cli run-single -c D2 --set holdout_v2_20261008   # 홀드아웃 v2 20문항
python -m sillok_rag.cli run-scenario -c D2 -s C                      # 역할 대화 시나리오(A·B·C 훈민정음, D·E 계유정난)
python -m sillok_rag.cli run-all --dry-run                            # 키 없이 전체 흐름 점검(C·D1·D2)
python -m sillok_rag.cli summarize results/<실험 폴더>/*.jsonl        # 자동 점검 합계(힌트)
python -m sillok_rag.cli grade-sheet results/<실험 폴더>/<파일>.jsonl # 사람 채점용 CSV
python scripts/retrieval_stage_diag.py --all --dry-run                # 정답 청크가 검색 어느 단계에서 빠지는지(무료)
```

- 개발 단발 115 + 대화 50을 한 번 돌리면 약 $0.26입니다. 결과는 덮어쓰지 않고 실험마다 새 폴더에 남습니다.
- 측정 때의 코드는 개발용 비공개 저장소의 태그 `freeze-20261007`입니다(이 공개 저장소는 정리한 최종본만 올려 그 이력이 없음). 그 뒤로 검색·답변 동작은 바꾸지 않았습니다.

### 데이터 다시 만들기

```bash
python scripts/extract_articles.py <실록 원문 ZIP>   # 고른 기사 → data/raw_xml/, data/articles.jsonl (원문 ZIP 필요)
python scripts/chunk_articles.py --tag <새 이름>     # 정제·청킹 (data/raw_xml/만 읽음)
python scripts/build_corpus.py                       # 청크 + 번역 원본(data/번역/) → data/corpus.jsonl
python scripts/data_table.py                         # 데이터 표(엑셀)
```

번역·화자·시점을 고치면 `build-db`(유료)를 다시 해야 합니다. 쉬운 말 풀이와 메모는 검색 DB에 들어가지 않아 다시 만들 필요가 없습니다.

### 테스트

```bash
python -m pytest -q    # API 키·검색 DB 없이 돎
```

## 폴더

| 경로 | 내용 |
|---|---|
| `sillok_rag/` | 검색·프롬프트·대화·평가·채점 엔진 |
| `app.py`, `ui/` | 화면 '역사 취재록'(Streamlit). 사건 데이터, 취재 화면 컴포넌트, 그림(`ui/assets/sized/`) |
| `data/` | 코드가 읽는 파일: 원문 XML, 코퍼스(`corpus.jsonl`), 번역 원본(`번역/`), 평가셋(`eval/`) |
| `results/` | 실험마다 폴더 하나: 답변, 채점, 실행 조건 |
| `scripts/` | 데이터 준비(추출·청킹·코퍼스·풀이), 검색 진단, 데이터 표 |
| `tests/` | 자동 테스트 |

| `archive/` | 끝난 실험(파일럿 1-7차, 새 코퍼스 1-4차)과 옛 도구 |

## 만든 방식

개발 비전공자인 저자가 AI 코딩 도구(Claude Code, Codex)와 함께 만들었습니다. 설계·검수와 구현을 다른 모델에 나눠 맡기고, 저장소의 문서(작업기록·결정)로 도구 사이에 작업을 이어 갔습니다. 공통 작업 규칙은 [AGENTS.md](AGENTS.md)에 있습니다. 번역은 AI 초안이고, 사람 검수는 [데이터](docs/데이터.md) 2절에 적은 범위만 했습니다.

## 출처와 라이선스

- **실록 원문**: 국사편찬위원회 「조선왕조실록」 원문(공공데이터포털 제공, 공공누리 제1유형: 출처 표시). `data/raw_xml/`, `data/articles.jsonl`과 코퍼스의 `original` 칸.
