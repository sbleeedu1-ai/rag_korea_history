## 무엇을 바꿨나

- 검색기만 바꿨습니다. 프롬프트(v3), 모델, top_k 4는 3차와 같습니다.
- **하이브리드 검색**: 임베딩 순위와 BM25 순위를 합쳐서 위 4개를 고릅니다. 두 검색기의 점수 단위가 달라서, 점수 대신 순위만 씁니다(RRF, 흔히 쓰는 기본값 60).
  - 청크 점수 = 1/(60 + 임베딩 순위) + 1/(60 + BM25 순위)
  - 시점 필터(D1·D2)는 두 검색기 모두에 그대로 적용됩니다.
- 비교용으로 **BM25만** 쓴 실행도 같이 돌렸습니다. 순위 진단에서 BM25가 유난히 잘 찾았기 때문입니다.
- 코드: `sillok_rag/retrieval.py`의 `HybridRetriever`, 실행은 `python -m sillok_rag.cli run-all --retriever hybrid --conditions C D1 D2`

## 문항별로 달라진 것

**좋아진 문항 (하이브리드)**
- Q9(의금부에 갇힌 사람), Q19(만리 번역), G5(글자를 만든 이유): 검색 실패 → 정답
- Q16(상소 때 초수리에 있었나): 모든 조건이 "거둥 전"이라고 바로잡음
- A5(27자)·A6·A8: 모든 조건 정답, 역할 대화 누설 없음

**여전히 못 찾는 문항 (하이브리드)**
- Q4(김문), Q12(최만리 파직?): 임베딩이 12-13위로 너무 낮게 봐서, BM25 1위와 합쳐도 4위 안에 못 듭니다. BM25만 쓰면 Q4는 맞힙니다.

**근거가 들어왔는데 답이 틀린 문항** (다음 실험 대상)
- Q15(반포 이후 상소?): 하이브리드는 c01·c19를 가져왔는데 "확인되지 않는다"(과잉 보류). BM25만은 "반포 이후가 맞다"고 틀린 전제를 받아들임.
- Q12(최만리 파직?): BM25만은 c15를 가져왔는데 보류(과잉 보류).
- Q14(사형 이유): BM25만은 없는 사형을 받아들임(전제 수용).
- Q13(한글을 없애자 했나?): 임베딩만일 때 1위였던 c03("신묘하다"고 인정한 부분)이 빠지면서 "없애자고 한 게 아니다"라는 교정이 사라짐.

**BM25만 쓸 때의 약점**
- Q8·A5(상소에 쓴 글자 수 "27자"): 질문에 "27"이 없으니 글자 겹침으로는 c07을 못 찾습니다. 임베딩은 1위로 찾습니다. 뜻으로 찾는 능력이 필요한 문항입니다.

## 결론

1. **하이브리드를 기본 검색기로 쓰는 것을 추천합니다.**
   - BM25만 쓴 것과 점수 차이는 1점 안팎이라 실행마다 생기는 흔들림 안에 있습니다.
   - BM25만 쓰면 "27자"처럼 뜻으로만 찾을 수 있는 문항을 놓칩니다. 앞으로 문서가 50-100개로 늘고 질문이 다양해지면 이 약점이 커질 것으로 봅니다(추측).

2. Q4·Q12처럼 임베딩이 아주 낮게 보는 문항까지 잡으려면 BM25 쪽에 가중치를 더 주는 방법이 있습니다. 다만 21문항에 맞춰 숫자를 고르면 평가셋에만 맞춘 결과가 되므로, 문서 확장 뒤 새 평가셋으로 정하는 것이 맞습니다.
