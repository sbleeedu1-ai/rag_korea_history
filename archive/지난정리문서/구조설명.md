# 코드 구조 설명

이 문서는 "어떤 파일이 무슨 일을 하고, 질문 하나가 어떤 길을 거쳐 답이 되는지"를 설명합니다.

## 1. 한눈에 보는 흐름

```
[준비 단계: 한 번만]
 공공데이터 실록 ZIP (한문, 143MB)
   │  scripts/extract_articles.py   ← 필요한 기사 7건만 뽑기
   ▼
 data/articles.jsonl + data/raw_xml/
   │  (AI 초벌 번역 + 화자·사건 시점 표시, 사람이 고칠 수 있는 파일)
   ▼
 data/corpus.jsonl  ── 청크 23개 (원문 / 번역 / 화자 / 사건 시점)
   │  python -m sillok_rag.cli build-db   ← OpenAI 임베딩으로 벡터 만들기
   ▼
 chroma_db/  ── 로컬 벡터 DB (검색용)

[질문 단계: 질문할 때마다]
 사용자 질문
   │  chat.py: 조건(A~D2)에 따라 "모델에게 줄 자료"를 고름
   │    A: 원문 전체 / B: 번역 전체 / C: 검색 상위 4개
   │    D1: C + 장면 이후 자료 빼기 / D2: D1 + 해설자 분리
   ▼
 prompts.py: 규칙 문장 + [자료] 를 붙여 시스템 프롬프트 완성
   ▼
 llm.py: gpt-4o-mini-2024-07-18 호출
   ▼
 답변 + 근거 청크 목록 → 화면(app.py) 또는 결과 파일(results/)
```

## 2. 청크 하나는 이렇게 생겼어요

`data/corpus.jsonl`의 한 줄 = 청크 하나입니다. (예: 다음 날 석방 부분)

| 칸 | 값 | 의미 |
|---|---|---|
| chunk_id | c15 | 청크 번호 |
| article_id | wda_12602020_001 | 실록 기사 ID (세종 26년 2월 20일 첫 기사) |
| paragraphs | [9, 10] | 원문 몇 번째 문단인지 |
| record_date | 1444-02-20 | 기사에 적힌 날짜 |
| event_order | 40 | **실제로 일이 일어난 시점** (40 = 2월 21일) |
| speaker | 사관(서술) | 누가 한 말인지 |
| original | 翌日, 命釋之, 唯罷昌孫職。… | 한문 원문 |
| translation | 이튿날 명하여 이들을 석방하게 하되… | 우리가 만든 번역 |

`record_date`와 `event_order`를 따로 두는 게 핵심이에요. 2월 20일 기사 안에 다음 날 석방 이야기가 같이 들어 있어서,
기사 날짜만 보면 "2월 20일의 최만리"가 석방 사실을 알아 버리거든요.

사건 시점 번호: 10 창제(1443) · 20 운회 번역 명령(2/16) · 30 상소 제출(2/20) · 31 세종 논박·하옥(2/20 오후) ·
40 석방·파직(2/21) · 41 김문 처벌(2/21) · 50·60 초수리 거둥·도착 · 70 훈민정음 완성(1446)

## 3. 조건 A~D2가 다른 점

| 조건 | 모델이 받는 자료 | 비유 |
|---|---|---|
| A | 한문 원문 23개 전부 | 한문 책을 통째로 줌 |
| B | 번역문 23개 전부 | 번역본을 통째로 줌 |
| C | 질문과 비슷한 번역문 4개 | 사서가 관련 페이지 4장만 찾아 줌 |
| D1 | C인데 장면 이후 페이지는 빼고 찾음 | "2월 20일 이후 기록은 서가에서 치워 둠" |
| D2 | D1 + "역할 벗고 알려줘" 같은 요청은 해설자가 따로 답함 | 해설자와 인물이 서로의 대화를 못 들음 |

D2가 필요한 이유: 범용 AI 테스트에서 B5("역할 벗고 실제 역사 알려줘") 뒤에 B6에서 인물이 미래를 아는 채로 말하는 오염이 4개 중 3개 조건에서 나왔죠.
D2는 해설자 답변을 인물의 대화 기록에서 빼서 이 문제를 막아 보는 설계입니다.

## 4. 파일별 역할

| 파일 | 하는 일 |
|---|---|
| `scripts/extract_articles.py` | 원본 ZIP에서 기사 7건을 뽑아 `data/`에 저장 |
| `data/corpus.jsonl` | 번역 청크 23개. **번역을 고치고 싶으면 이 파일을 고친 뒤 build-db를 다시 실행** |
| `data/eval/single.jsonl` | 단발 질문 25개 + 정답·근거 청크 (DB에는 안 들어감) |
| `data/eval/holdout.jsonl` | 검증용 5문항. 튜닝 끝나고 마지막에만 사용 |
| `data/eval/scenarios.json` | 다회차 시나리오 A·B·C (설정 문구 + 10턴) |
| `sillok_rag/config.py` | 모델 이름, 검색 개수(4), 경로 같은 설정값 |
| `sillok_rag/corpus.py` | jsonl 파일 읽기, 출처 표기, 실록 사이트 링크 만들기 |
| `sillok_rag/store.py` | Chroma 벡터 DB 만들기 (청크마다 사건 시점을 메타데이터로 저장) |
| `sillok_rag/retrieval.py` | 검색기 2개: Chroma(의미 검색), BM25(키 없이 쓰는 글자 검색). 둘 다 시점 필터 지원 |
| `sillok_rag/prompts.py` | 규칙 문장(사실 질문용 / 인물용 / 해설자용)과 [자료] 블록 만들기 |
| `sillok_rag/chat.py` | 조건별로 자료를 고르고 대화 기록을 관리. D2의 해설자 분리도 여기 |
| `sillok_rag/llm.py` | OpenAI 호출. dry-run이면 호출하지 않음 |
| `sillok_rag/evaluate.py` | 실험 실행, 자동 점검(미래 단어·원문에 없는 한문 인용·근거 검색 여부), 채점 CSV |
| `sillok_rag/cli.py` | 명령어 모음 (`build-db`, `ask`, `run-all`, `summarize`, `grade-sheet`) |
| `app.py` | Streamlit 화면: 대화 / 조건 비교 / 실험 결과 / 자료 보기 |
| `tests/` | 자동 테스트 15개 |

## 5. 실험 한 번 돌리는 순서

1. `python -m sillok_rag.cli build-db` → Chroma DB 생성
2. `python -m sillok_rag.cli run-all` → `results/`에 조건별 결과 파일이 생김
3. `python -m sillok_rag.cli summarize results/*.jsonl` → 자동 점검 합계 확인 (힌트일 뿐)
4. `python -m sillok_rag.cli grade-sheet results/<파일>.jsonl` → 엑셀로 열어 사람이 최종 판정 기록
5. 결과를 보고 번역·검색·프롬프트 중 어디를 고칠지 결정 (판단 기준은 `docs/EXPERIMENT.md`)
