1. **X1·X2 — 마지막 교체 단계에서도 기존 자료를 지켜야 한다.** 중간 생성 실패 보호는 이미 있지만, 기존 것을 지운 다음 새 이름으로 바꾸다 실패하는 빈틈이 남아 있다.
2. **X3·X4 — 결과 파일 이름 충돌과 덮어쓰기를 막아야 한다.** 기존 기록에 나온 문제이며 현재 코드에도 남아 있다. 정상적인 순차 측정이 항상 충돌한다는 뜻은 아니다.
3. **X6 — 실행 조건 기록이 실제 검색·평가 입력을 충분히 구별하지 못한다.** DB 일치용 지문을 그대로 확대하기보다 코드·설정·평가셋·검색 입력을 별도로 기록하는 편이 맞다.

## 유지할 것과 정리 순서

- `data/` 최상위의 기사·청크 초안·코퍼스, 원문 XML 132개, 번역 13개는 코드가 실제 읽는다. 이름이 오래됐다는 이유만으로 옮기지 않는다. 최종 평가셋도 유지한다.
- `results/`는 이미 실험별 32개 폴더로 모여 있고 확인한 사람 채점표에 고아 파일이 없었다. 오래됐다는 이유만으로 결과·채점표를 다시 합치거나 지울 근거는 찾지 못했다. 옛 옵션 제거는 옛 결과 파일 보존과 별개다.
- `requirements.txt`의 7개 의존성은 실제 import가 있고 `pytest.ini`, `.env.example`, `AGENTS.md`, `CLAUDE.md`의 역할도 분명하다. 현재 확인 범위에서 삭제·합침을 제안하지 않는다.
- `retrieval_stage_diag.py`는 현역 무료 진단과 공유 `CachedEmbedder`가 있어 통째로 보관 이동할 대상으로 잡지 않았다. 실제 장면 전달과 무료 실행 차단은 이미 반영돼 있다.
- `chunk_articles.py`는 길다는 이유로 나누지 않는다. 청킹·수동 경계·규칙 순서·프롬프트 문장·번역·풀이·기존 결과는 그대로 둔다. 전제 검증과 근거 표시의 `_squash()`도 지우는 문자가 서로 달라 단순 중복으로 합치지 않는다.
- 사용자 자료·비밀 파일·실제 DB·캐시는 정리 대상에서 제외한다. 나중에 그 위치나 수명을 정리하려면 **사용자 확인 필요**다.

사용자가 두 검토를 비교해 범위를 정한 뒤, 파일 이동·옛 선택지 제거·공통 함수 추출을 각각 작은 단위로 진행하는 편이 맞다. 실제 기본 동작은 위의 바이트 재생성과 후보·메시지 비교로 보존한다. X1-X16 같은 오류 수정과 실행 기록 보강은 별도 변경으로 구분한다. 이미 해결한 DB 임베딩 실패 보호, 사람 채점표 덮어쓰기 방지, 빈 판정 집계, 코퍼스 불일치 차단, 진단 장면 누락을 미해결 문제로 다시 올리지 않는다.
