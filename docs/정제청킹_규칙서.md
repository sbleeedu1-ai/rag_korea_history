# 정제·청킹·메타데이터 규칙서 (v2, 2026-09-30)

실록 기사를 챗봇이 찾아 쓸 수 있는 조각(청크)으로 만드는 규칙입니다. 로드맵 3단계(정제 규칙·청킹·메타데이터·청크 통계·수동 검사표) 산출물입니다.

v2는 2026-09-30 사람 검수 242곳([작업기록](기록/작업기록.md) [118])에서 나온 문제로 v1.1(2026-09-29)을 고친 것입니다. v1.1과 무엇이 달라졌는지는 **9장**, v1.1 원문 전체(기존 기준 15가지, 파일럿 비교, 전략별 같은 장면 비교 등)는 `archive/새코퍼스_1-4차_793청크/정제청킹_규칙서_v1.1_와_v2변경.md`에 있습니다.

## 1. 전체 흐름

```
실록 ZIP(국사편찬위원회 XML, 한문) → 기사 132건만 data/raw_xml/ 로 잘라 둠 (scripts/extract_articles.py)
  │ ① 정제: 깨진 글자·교감 표시 정리, 필요 없는 주석 빼기          (3장)
  │ ② 나누기: 말하는 사람·시점·날짜·인용 단위로 청크 만들기         (4장)
  │ ③ 메타데이터: XML에서 가져온 칸 + 새로 붙인 칸                (2장, 5장)
  ▼
청크(원문)  data/청크초안_20260930_v2.jsonl   ← scripts/chunk_articles.py (data/raw_xml/ 읽음, ZIP 필요 없음)
  │ ④ 번역(AI 초안) + 화자 한글 이름 + 사건 시점·알게 되는 때     (4-6)   ← data/번역/*.jsonl
  │ ⑤ 제목·화자·번역문을 임베딩, BM25는 여기에 기록일·재위년과 한문 원문까지 (머리말 칸 자체는 검색에 안 들어감, 4-5) ← scripts/build_corpus.py, build-db
  ▼
data/corpus.jsonl → Chroma DB
```

규칙을 바꿔 다시 자르면 청크 ID가 바뀝니다. 그때는 ① 원문이 같은 청크는 번역을 그대로 옮기고 ② 경계가 바뀐 청크만 번역을 나누거나 잇고 ③ 평가셋의 정답 청크 ID를 대응표로 바꿉니다. v2에서 이렇게 했고 도구는 `archive/새코퍼스_1-4차_793청크/scripts/`에 있습니다(9장).

## 2. XML에서 그대로 가져오는 것

| 청크 칸 | XML 어디에 | 예 | 비고 |
|---|---|---|---|
| `article_id` | `level5/@id` | wda_12602020_001 | 태조실록 총서는 `level3`이 기사 단위 |
| `record_date` | `dateOccured/@date` | 1444-02-20L0 → 1444-02-20 | 끝의 L1은 윤달 → `leap_month`. 총서는 날짜 없음 |
| `day_ganji` | 본문 첫머리 `○庚子/` | 庚子 | 본문에서 떼어 칸으로 |
| `title_ko` | `mainTitle` | 집현전 부제학 최만리 등이… | 국사편찬위원회의 **한글 요약 제목**(번역문 아님) |
| `source` | `source` 첫째 | 태백산사고본 世宗實錄 33책 103권 19장 B면 | |
| `king`, `reign` | 출처의 실록 이름 + 기사 ID | 세종, 세종 26년 | ID 5-7번째 글자가 재위 연도 |
| `subjects` | `subjectClass` | 어문학-어학(語學) | 여러 개 |
| `persons` `places` `books` | `index/@type` | 崔萬理, 椒水里, 《三綱行實》 | 청크에 실제로 나오는 것만. v2: 긴 이름에 들어 있는 짧은 이름(成三問 / 三問)은 뺌 |
| 편찬자 주석 | `annotation type="원주"`, `소자쌍행` | 【其母入江都故也。】 | 원문의 일부라 【】째 남김 |
| 사론 | `postScript` 또는 【史臣曰…】 | 【史臣曰: …】 | 본문과 따로 청크 |

XML에 **없는** 것: 기사 안에서 누가 말하는지, 그 말이 실제로 언제 있었던 일인지, 인물이 언제부터 그 사실을 알 수 있었는지. 4장의 규칙이 필요한 이유입니다.

## 4. 청크 나누기와 새로 붙이는 것

### 4-1. 나누는 순서

1. **기사 경계**: 청크는 기사를 넘지 않는다.
2. **문단**: XML 문단이 첫 단위. 말머리만 있는 문단(`…上疏曰:`)은 뒤따르는 본문 문단과 합친다.
3. **말머리**: 문단 안에서 `X曰:` `X啓曰:` `X議:` `X啓:` `X言:`이 나오면 그 구절 시작에서 끊는다. 따옴표 안(남의 말 속)의 曰은 끊지 않는다.
   - 【】 밖의 말머리는 구절 시작을 찾을 때 **【】 안의 마침표를 문장 끝으로 보지 않는다**(v2. 청크가 `】曰`로 시작하던 것을 막음).
   - 말이 끝난 뒤 서술이 60자 이상 이어지면 서술을 떼어 내되, **그 문장이 끝나는 곳(。)에서** 뗀다(v2. `"義不可殺" / , 力止之` 방지).
4. **시점이 바뀌는 말**: `翌日` `明日` `初,` `先是` `前此` `至是` `是後` `其後` `後日`에서 끊는다. **문장 첫머리이고 따옴표·【】 밖일 때만**(v2. 쉼표 뒤 `至是`에서 문장 가운데가 잘리던 것을 막음).
5. **서술 속 날짜**(v2): 따옴표·【】 밖에서 문장이 날짜로 시작하면(`初八日,` `七月初六日,` `二十九日,`) 끊는다. 달 없는 `一日`(하루는)은 뺀다. 한 청크에 여러 날의 전투가 섞이던 것(한산도 기사)을 막음.
6. **짧은 조각**: 30자 미만 조각은 앞 조각에 붙인다. 단, 시점이 바뀌는 말이나 날짜로 시작하는 조각, 사론은 따로 둔다. 기사 첫머리의 짧은 서술(`設宣惠廳。`)은 다음 조각에 붙이되, **다음 조각이 先是·初 등으로 시작하면 붙이지 않는다**(v2. 7/17 즉위 문장과 7/12 회상이 한 청크여서 7/12 장면에 즉위가 보였음).
7. **인용 단위**(4-3): 한 사람의 말 안에 다른 사람 말 인용이 2개 이상이면 인용마다 쪼갠다.
8. **길이**: 400자(공백 뺀 한자 수)가 넘으면 `一,`(상소의 조목) 시작이나 문장 끝(。?!)에서 비슷한 길이로 나눈다. 나눈 조각이 닫는 따옴표(`’"`)로 시작하면 그 따옴표를 앞 조각으로 옮긴다(v2, 자르는 위치는 그대로).
   - 400·30의 근거: 파일럿 23개가 원문 11-413자, 평균 150자였고 그 크기로 검색이 16-19/21 맞았음.
9. **사람이 정한 경계**(4-7): 뜻을 읽어야 알 수 있는 경계는 기사별로 "이 말 앞에서 자르기 / 이 말로 시작하면 앞에 붙이기"를 코드의 표(`MANUAL`)에 적는다. 표의 말을 원문에서 찾지 못하면 프로그램이 멈춘다.

### 4-2. 화자

자동으로 초안을 달고(원문 한자), 번역 단계에서 사람·AI가 다시 읽어 한글(漢字)로 고칩니다. 고친 곳은 note에 "화자 초안 '…' → …"로 남고, 초안은 `speaker_draft`에 남습니다.

| 화자 종류 | 알아보는 법 (말머리 앞 구절) | 예 |
|---|---|---|
| 임금 | `上曰` `傳曰` `敎曰` `御製` `備忘記` `綸音` | 上曰: → 세종 |
| 왕실 | 大王大妃·王大妃·世子 등 | 大王大妃曰: → 대왕대비 |
| 신하 | 색인에 있는 사람 이름 | 萬理等對曰: → 萬理 등 |
| 관청 | 備邊司·義禁府·戶曹 등 | 義禁府劾啓: → 의금부 |
| 상소 | `上疏` `上箚` `交章` `封疏` | 최만리 등(상소) |
| 문답 | 짧은 말(30자 미만)이 여럿 붙어 한 청크에 말한 사람이 둘 이상 | 신경희·선조 |
| 이어서 | `又曰` `其一曰` | 앞 화자를 물려받음 |
| 사관(서술) | 말머리가 없는 부분 | 車駕至椒水里。 |
| 사관(사론) | `史臣曰`, `postScript` | 【史臣曰: …】 |
| 기타(확인필요) | 위 어디에도 안 맞음 | 覘者曰(정탐꾼) |

v2 결과(초안 기준): 신하 261 · 서술 174 · 문답 123 · 임금 107 · 상소 47 · 기타 36 · 왕실 28 · 관청 22 · 사론 5.

**화자와 인용된 사람은 칸이 다르다**: 김종서가 세종의 전지를 옮기며 답하면 화자 = 김종서, 인용된 사람 = 세종(전지). 사관의 간접 서술("남구만도 그르다고 여겼다")은 직접 발언이 아니므로 사관(서술)으로 본다(2026-09-30 검수에서 합의).

### 4-3. 인용 단위 쪼개기 (사용자와 합의한 규칙)

한 사람이 말하는 도중 다른 사람의 말(`X曰: ‘…’`)을 2개 이상 인용하면, **"인용 + 그 인용에 대한 화자의 말"**을 한 청크로 쪼갭니다. 다음 인용이 시작되기 직전까지를 한 덩어리로 하고, `quoted`(인용된 사람) 칸을 붙입니다. 인용이 하나뿐이면 쪼개지 않습니다.

이유: 파일럿 Q4("불가하지 않다"고 말한 사람 = 김문)가 계속 틀렸습니다. 한 덩어리 안에 김문 인용은 한 줄뿐이고 나머지는 정창손 이야기라 검색에서 13위로 밀렸습니다. 쪼갠 뒤 김문 인용 청크가 따로 생겼습니다(`wda_12602020_001-11`). v2에서 인용 단위로 쪼갠 청크는 31개입니다.

### 4-4. 사건 시점과 알게 되는 때

| 칸 | 뜻 | 누가 채우나 |
|---|---|---|
| `record_date` | 기사에 적힌 날짜 | XML 그대로 |
| `event_date` | 그 일이 실제로 일어난 때 | 번역 단계(AI 초안) |
| `known_from` | 이야기 속 인물이 그 사실을 **알 수 있게 되는 때** | 번역 단계. 역할 대화의 시점 필터(D1·D2)가 이 칸으로 거름 |

`known_from` 쓰는 법(코드는 `sillok_rag/corpus.py`의 `known_key`로 숫자로 바꿔 비교):

| 모양 | 예 | 언제부터 보이나 | 쓰는 곳 |
|---|---|---|---|
| 날짜 | `1444-02-20`, `1795-윤02-12` | 그날 | 기본(윤달은 `윤`을 붙임) |
| 날짜 + `이전` | `1444-02-20 이전` | 그날 바로 앞 | 先是·初·前此로 시작하는 배경 |
| 날짜 + `오후` | `1444-02-20 오후` | 같은 날 안에서 뒤 | 같은 날 순서가 필요할 때(상소 뒤의 논박·하옥). 시각이 아니라 순서 표시 |
| 날짜 + `이후` | `1776-03-10 이후` | 그날 뒤 | 기사 날짜보다 앞선 일이 바로 뒤에 이어질 때(즉위 직후의 명). **뒷날의 결과 평가(是後…)는 `이후`가 아니라 `후일 기록`**(다음 날부터 보여 버림, 2026-09-30) |
| 달만 | `1446-09` | 그달 1일 | **是月(이달) 기사에만** |
| 범위 | `1592-05-06~05-29` | **끝 날짜** | 여러 날·여러 해가 섞인 청크 |
| `후일 기록(…)` | `후일 기록(사론)` | 역할 대화에서 늘 뺌(해설자만) | 장면보다 뒤에 쓴 글: 사론, 졸기, 총평(연산군, 선혜청 설치 뒤의 결과), 원주의 후일 평가, 편찬 때 덧붙인 사실(경복궁 궁성·광화문) |

### 4-5. 맥락 머리말

청크 앞에 한 줄을 붙여 짧은 청크도 "언제, 무슨 일, 누가"를 알 수 있게 합니다.

**실제 쓰임(2026-10-01 바로잡음)**: 처음에는 임베딩과 BM25를 "머리말 + 번역문"으로 만들 계획이었지만, 지금 코드의 검색용 글(`corpus.search_text`)은 **기사 제목 · 화자 · 번역문**이고(BM25는 한문 원문도 더함), 머리말 칸(`header`)은 자동 채점기 입력에만 쓰입니다. 날짜가 검색에 안 들어가 연도로 묻는 F43이 틀리던 문제는 2026-10-01에 **BM25 색인에만 기록일·재위년을 넣어** 고쳤습니다(`retrieval.date_text`, 예 "1466년 8월 25일 세조 12년", 작업기록 [183]). 임베딩 본문에는 여전히 날짜가 없고, 인용된 사람은 어느 검색에도 들어가지 않습니다.

형식: `[날짜 · 왕 재위년 · 기사 제목 · 말한 사람: 화자 · 인용: 인용된 사람]`

```
[1444년 2월 20일 · 세종 26년 · 집현전 부제학 최만리 등이 언문 제작의 부당함을 아뢰다 · 말한 사람: 세종 · 인용: 김문]
[1651년 8월 4일 · 효종 2년 · 이완을 특별히 서용하여 어영 대장에 임명하다 · 말한 사람: 사관(서술)]
```

- 두 번째는 원문이 12자뿐인 기사입니다. 머리말이 없으면 무슨 맥락인지 검색에 잡히기 어렵습니다.
- 화자·인용된 사람은 번역 단계의 한글 이름을 씁니다. 그 시점 호칭도 괄호로(1453년의 世祖 → 수양대군(首陽大君, 세조)).

'서울'은 조선의 서울(지금의 서울)에만 쓰고 다른 나라·고려의 수도는 '수도'("송나라 수도", "고려의 수도 개경", [260]). 풀이 속 인물에는 시대·나라를 붙인다("중국 송나라 학자 주희", "조선 학자 이이의 시호", [262]-[263]) | 풀이는 모델에게 안 가므로 누설이 없고, "정조가 세운 ~" 같은 질문에도 걸림. 풀이를 모델 자료에 넣기로 하면 인물 대화에서는 빼거나 괄호 속 뒷날 이름을 지운다 |
| G6 | **같은 용어는 같은 풀이.** 단 문맥 뜻이 비슷할 때만 맞추고, 다르면 "원래는 ~. 여기서는 ~"로 나눈다. 일괄로 바꾸지 않는다 | 반열: 늘어선 줄 / 지위·등급 / 벼슬자리로 나눔 | 같은 말이 기사마다 다른 뜻으로 쓰임 |
| G7 | 확실하지 않으면 원문·실록 검색·사전(표준국어대사전·한국민족문화대백과)으로 확인한다. 사전 문장은 저장소에 옮기지 않는다 | 지부 = 김승규(같은 날 다른 기사 '知部金承珪') | 사전 문장 저작권 |
| G8 | 60자 안팎으로 짧게. 자세한 설명은 관련 용어의 풀이에 맡긴다 | 경재소: 유향소 설명은 유향소 풀이에 두고 뺌 | 화면 주석은 한눈에 읽혀야 함 |

**번역문과의 관계:** 번역문에 우리말 풀이만 있고 한자가 괄호로 붙은 용어("명부(衿案)")는 다른 용어처럼 "금안(衿案)"으로 바꾸고 우리말 풀이는 `gloss`로 옮깁니다. 인용 구절(同文同軌 등)은 괄호 읽기를 붙이지 않습니다. 번역문을 고치면 검색 본문이 바뀌어 DB를 다시 만들어야 하므로(유료), 대상을 `docs/기록/데이터가공/번역수정예정_한자표제어_20261006.csv`에 모아 두었다가 한꺼번에 고칩니다. `gloss`·`note`는 검색 지문에 들어가지 않아 바로 고쳐도 됩니다.

**도구와 기록:** 새로 넣기는 `scripts/gloss_add.py`(청크 단위), 고치기·빼기는 `scripts/gloss_fix.py`(용어 단위, `=이전 풀이`로 대상 지정), 그 뒤 `python scripts/build_corpus.py`. 용어마다 사전 대조와 사람 검수 결과(이전 풀이·판정·고친 풀이·확인한 곳·메모)는 `docs/기록/데이터가공/용어사전확인_20261006.csv`에 남깁니다.
