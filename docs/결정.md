# 결정과 과정

이 프로젝트에서 정한 것과 그 이유, 검토한 대안을 모았습니다. 다른 사람(이나 다른 AI)이 같은 고민을 반복하거나 이미 정한 것을 뒤집지 않게 하려는 문서입니다. 대괄호 번호(예: [210])는 [작업기록](기록/작업기록.md)의 항목 번호이고, 자세한 경과는 그곳에 있습니다.

## 데이터와 저작권

### 번역은 한문 원문만 보고 우리가 한다
- 실록 원문(공공누리 제1유형)만 보고 AI 초안으로 번역한다. 국역(ⓒ세종대왕기념사업회)·신역(한국고전종합DB) 번역문은 파일·DB·프롬프트·저장소에 넣지 않고 사람이 화면에서 대조만 한다. 한능검 기출 원문(공공누리 제4유형)도 넣지 않는다(회차·번호와 우리말 요약만). [4], [10]

### 기사는 한능검 출제빈도로 고른 132건
- 학습자가 실제로 묻는 주제를 담으려고 한능검 심화 65-79회 조선 문항 148개를 주제별로 세어 골랐고, 정답 내용이 자료에 들어가도록 근거 기사를 더했다(로드맵 목표 50-100건보다 많음). 대안: 주제 기준 82건만. [24]-[56]

### 번역 규칙
- 생략된 주어·대상은 `(김문이)`처럼 괄호로 채우고, 이름은 처음 나올 때 한글(漢字). 청크로 잘리면 앞 문맥이 사라져 모델이 주어를 질문 속 인물로 채우는 실패가 있었다(파일럿 7차). [62], [65], [86]
- 한자 용어는 읽기(漢字) + 뜻은 풀이로, 인명은 실록 국역 읽기를 기본으로 하되 공신력 있는 인물 자료가 일관되게 다르면 그 읽기(차이는 note에). 원문 오자는 원본 이미지나 독립 사료로 확인된 경우에만 번역문에 바른 글자를 쓴다. [297]-[299]
- 누구인지 밝히는 괄호(예: 용(瑢, 안평대군))를 87곳 보충해 D8 질문이 고쳐졌다. [309], [311]

### 쉬운 말 풀이는 번역문을 고치지 않고 청크에 붙인다
- 번역문은 원문 용어를 살린 현대 문장으로 두고, 모를 만한 용어는 `gloss` 칸에 풀이를 붙여 화면 주석과 검색에 함께 쓴다. 대안: 번역문을 쉬운 말로 풀어 쓰기(원문 용어가 사라져 검색·대조가 어려움), 질문 쪽 동의어 사전(처음 보는 질문에 약함). 쓰는 기준은 규칙서 4-8. [234], [238]-[241]

## 청킹과 코퍼스

### 청크 = 문단·화자 전환 + 인용 단위 + 맥락 머리말 (규칙서 v2)
- 말머리(曰·啓)로 화자가 바뀌는 곳에서 나누고, 다른 사람의 말을 인용한 부분은 한 번 더 쪼갠다. 너무 길면(400자 넘음) 문장 끝에서 나눈다. 파일럿에서 한 청크에 김문·정창손·세종의 말이 섞여 발언자를 착각한 실패 때문이다. [44]-[65]
- 대안 비교([217]): 같은 글자 양(3,500자)에서 정답 적중 지금 87 / 길이 묶기 81 / 기사 통째 77(/94), 리랭커 후보 20개 단계에서는 90 / 91 / 92로 거의 같아 지금 청킹을 유지했다.
- v2(2026-09-30, 793 → 803청크): 사람 검수에서 나온 경계 문제로 규칙을 고치고, 규칙으로 못 잡는 12개 기사는 사람이 정한 경계 표로. [118]-[122]

### 시점 필터는 `known_from`(인물이 알게 된 때)으로
- 역할 대화는 장면 시점보다 뒤에 알려진 청크와 "후일 기록"(사론·졸기·총평)을 검색에서 뺀다. 한 기사 안에 다음 날 일이 들어 있어 기사 날짜만으로는 미래 누설을 못 막기 때문이다. 범위 값은 끝 날짜로 연다. [13], [17], [87], [118]-[122]

### 코퍼스 줄 순서는 그대로, 새 기사는 끝에
- BM25 동점 청크가 줄 순서대로 다른 순위를 받던 문제가 있어 기준선과 비교가 흐려지지 않게 순서를 바꾸지 않는다. [139], [141]

## 검색과 답변

### 모델
- 답변·리랭커 `gpt-6-luna`(답변 생각 수준 medium, 리랭커 low), 임베딩 `text-embedding-3-large`, 자동 채점 `gpt-4o-mini-2024-07-18`, 벡터 DB는 로컬 Chroma(메타데이터로 시점 필터).
- 바꾼 이력: 임베딩 small → large(검색 적중 30 → 42/56, [96]), 답변·리랭커 gpt-4o-mini → gpt-6-luna(단발 56 → 61/67, 비용 약 30% 감소, [107]-[108]), 답변 생각 low → medium([305]-[309]). 대안: gpt-6-sol(가격 20배), 더 작은 nano 모델.

### 하이브리드 검색 → 리랭커가 6개를 고름
- 임베딩 순위와 BM25 순위를 RRF(공동 평균 순위)로 합친 상위 20 + 각 검색기 상위 10 + 풀이 BM25 상위 5를 후보로 두고, 리랭커(답변 모델)가 6개를 고른다. [32], [37], [100]-[101], [139]-[143], [302], [304]
- 이유: 리랭커로 검색 적중 44 → 54/56, 단발 47 → 56/67. 한쪽 검색기만 찾은 정답이 합치며 밀리던 문제 때문에 각 검색기 상위를 보존한다. top_k를 그냥 8로 넓히면 소음이 같이 들어왔다(파일럿 3차).
- BM25는 두 글자씩 자르기(bigram). 조사가 붙은 말도 잡고 새 의존성이 없다. 기록일·재위년도 BM25 색인에 넣는다([183]).
- 풀이 검색(C안): 합친 순위용 BM25에는 풀이를 넣지 않고, 풀이를 섞은 BM25를 따로 돌려 상위 5개를 후보에만 보탠다. 풀이를 BM25에 바로 섞는 B안은 한 문항을 고치는 대신 다른 문항을 잃었다. [286], [297], [302]
- 역할 대화에서 인물이 답하는 턴은 장면 설정 문장을 임베딩 검색어와 리랭커에 함께 준다("오늘 올린 상소"가 다른 상소를 찾던 문제, 역할 A·B·C 26 → 29/30). [182]-[184]

### 리랭커가 질문 속 전제도 판정한다
- 리랭커가 자료를 고르면서 질문 속 전제를 맞음·틀림·확인 불가로 판정하고, '틀림'이면서 근거 문장이 고른 청크에 있을 때만 답변 모델에 메모로 넘긴다. 전제가 여럿이면 하나씩 나눠 판정한다. gpt-4o-mini 때는 맞는 메모가 0개였으나 gpt-6-luna로는 12개 중 10개가 맞았다. 알고 채택한 위험: 메모가 틀리면 답이 따라간다(HF05 v1b). [104], [304]-[316]

### 사실 질문 규칙 v9, 역할 규칙 v8
- **사실 규칙**: 전제부터 확인하고, "기록에서 확인되지 않는다"는 관련 내용이 전혀 없을 때만. 틀린 전제는 "자료에 따르면 ○○가 아니라 △△입니다"로 바로잡되, 질문에 실제로 적힌 틀린 내용이 있을 때만(평범한 질문에 없는 대조를 지어내던 문제). 변천: v4([43]-[61]) → v8(첫마디 "아니다." 15/20 → 0/40, [211]) → v9(없는 대조 8 → 0, 사실 66/67, [230]-[232]).
- **역할 규칙**: 인물은 장면 시점까지만 알고, 자신의 앞선 답은 아는 사실이지만 상대(취재자)의 말은 확인할 대상이다(v7, [179]-[181]). 사관 서술의 뒷날 호칭(묘호·군호)을 쓰지 않는다(v8, [212], [309]). "이 인물이 이 시점에 아는 사실" 카드는 시스템 프롬프트에 둔다.
- 기각한 것: 다른 시대 함정을 모델 일반 지식으로 교정하게 한 v6(자료 없음 문항에서 틀린 사실을 지어냄), 조건을 좁혀 말버릇을 없앤 v6b(틀린 전제를 받아들이게 됨). [98]

### 해설자 이력 분리 (조건 D2)
- 실험 조건은 C(검색), D1(C + 장면 시점 필터), D2(D1 + 해설자 대화 이력 분리). 인물에게 "실제 역사에서는?"처럼 역할 밖 질문을 하면 해설자가 답하고, 그 문답은 인물 이력에 넣지 않아 미래 정보가 인물에게 넘어가지 않는다. 서비스는 D2를 쓴다. 조건 A(원문 전체)·B(번역 전체)는 803청크가 모델 입력 한도를 넘어 뺐다. [19], [87], [105]

## 평가

### 개발셋·검증셋·홀드아웃을 나눈다
- 개발셋 v3는 반복 개선에 쓴 문항이라 새 질문 성능을 말할 수 없다. 그래서 v3가 쓰지 않은 한능검 문항을 반으로 나눠 A는 검증셋 v1, **B는 봉인**했다. v1도 실패를 보고 고쳤으므로, 최종 측정의 홀드아웃 v2는 봉인한 B로 만들어 동결 코드로 **한 번만** 돌렸다. [114]-[130], [288], [330]-[331]
- 두 번째 사건(계유정난) 시나리오 D·E는 개발 문항과 질문이 겹치지 않게 테스트로 고정하고, 처음 보는 사건에서 ChatGPT와 같은 질문으로 비교하는 데 썼다. [186], [188]

### 채점: Claude가 합의 기준으로, 홀드아웃은 사람도
- LLM 자동 채점기는 역할 대화에서 사람·Claude와 일치가 66%로 낮아 참고용으로만 쓴다. 공식 숫자는 Claude가 합의 기준표([210], [데이터](데이터.md) 3절)로 모든 답을 읽어 채점하고, 홀드아웃 v2는 사용자가 AI 판정을 가린 채 따로 채점했다. [91], [210], [317]-[318], [332]
- 다른 시대 함정(건원중보를 조선 일로 묻기 등)은 "자료에 없다"만 해도 정답이다. 정확한 시대 교정은 실록 밖 지식이라 요구하지 않는다. [210]
- 결과·채점표는 덮어쓰지 않고 실험마다 `results/<날짜>_<실험 이름>/`에 새로 남긴다. [22], [26], [177]

### 지표
- 발언자 귀속(답이 기록상 발언자를 대는가)과 화자 라벨(청크의 `speaker`·`quoted`가 원문과 맞는가)을 나눠 잰다. 근거 표시 정확도는 별도. [186], [190]-[191], [204]-[207]

### ChatGPT 비교 조건 (2026-10-08)
- ChatGPT 화면에서 **웹 검색을 끈 답이 기본**, 켠 결과는 따로 적는다. 유료(GPT-6 Sol, 생각 수준 High — 결과를 보기 전에 정함)·무료(GPT-5.6 Luna + Think) 둘 다, 질문마다 새 임시 채팅, 우리와 같은 앞머리 문장. 정답만 센다(부분은 정답 아님). [330]-[342]

## 서비스

### 기자 취재형 학습 서비스, 주장은 정확도 1위가 아니라 근거·학습 흐름·비용
- 제안서의 "사관이 되어 인물을 인터뷰"를 **기자가 사건 속 인물을 취재하고 수첩을 완성하는 서비스**로 구체화했다. 주장은 "범용 AI보다 정확하다"가 아니라 **근거를 검증할 수 있게 보여 주고, 학습 흐름으로 설계하고, 작은 모델로 싸게**다. 웹 검색을 켠 ChatGPT보다 낫다고 할 근거는 없다. [0], [185], [188], [192]

### 취재 완료는 큰 줄기를 채우면, 저장은 나중에
- 수첩의 큰 줄기 세 개를 근거와 함께 확인하면 취재 완료. 클릭·질문 횟수만으로 완료시키지 않고, 이해도 점수·정리 활동은 넣지 않는다. 접속을 끊은 뒤 이어 하기는 서비스 완성 뒤 시간이 남으면 검토한다. [201], [202]

### 화면: 개발용 시나리오·함정 질문은 쓰지 않는다
- 화면에는 개발 시나리오 A-E와 함정 질문을 그대로 쓰지 않고 학습자용 추천 질문을 새로 쓴다. 목표 체크는 질문·버튼이 아니라 실제 답의 근거 판정으로 한다(호출 1번 추가). 취재 화면은 Streamlit 커스텀 컴포넌트로 직접 그린다(대안: CSS로 위젯 덮기 — 정렬 한계, React + Python 서버 — 의존성·일정). [355]-[366]
- 근거 보기의 내부 표시는 네 가지(실록 기록 / 실록 풀이 / 인물 시점 / AI 창작)이고, 화면에는 근거 기사만 보인다. 인물의 앞선 답은 실록 기록의 근거로 쓰지 않는다. [196], [204]-[207]

### 측정 뒤로 미룬 것
- 측정 중 찾은 번역·풀이 문제는 동결 중 고치지 않았다(번역문이 검색 본문이라 고치면 측정 대상이 바뀜). 목록은 [한계와 다음 과제](한계와_다음과제.md). [330]
- 인용된 사람(`quoted`) 칸에 고전 인용을 넣을지, 역할 대화 자동 채점 보강, 역할 대화의 다른 시대 기사 범위는 측정과 관계없어 정하지 않았다. [317]

## 작업 방식

- **저장소가 기준**: 여러 AI 도구(Claude Code, Codex)를 번갈아 써서 채팅 기억이 아니라 코드·커밋·문서로 이어 간다. 공통 규칙은 `AGENTS.md`. [71], [78], [82], [89]
- **설계·검수와 구현을 나눈다**: 설계·검수(번역·역사 판단·채점 포함)와 구현을 다른 모델에 맡기거나, 한 모델이면 계획 → 구현 → diff 검수 순서를 지킨다. [92], [110], [169]
- **담당**: 번역·풀이는 Claude, 튜토리얼 데이터화는 Codex(10-06). [290]
- **폴더**: `data/`는 코드가 읽는 입력, `results/`는 실험 산출물(실험마다 폴더 하나), `docs/기록/`은 사람이 보는 기록과 근거 표. 더 쓰지 않는 파일은 지우지 않고 `archive/`로. [136]-[177]
- **확인 시점**: 일반 작업은 로컬 커밋까지 스스로 진행하고, 비용이 드는 실행은 금액과 관계없이, 원격 푸시·PR·main 병합은 먼저 확인한다. [93], [146]
